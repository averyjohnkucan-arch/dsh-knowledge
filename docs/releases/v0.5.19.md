# v0.5.19 — Settings reconciliation and metadata write reduction

An embedding/chunking settings change followed by Sync now reuses saved parser/OCR evidence when source bytes and processor options are unchanged. New source bytes or changed processor options still use the strict reparse path. Active imports retain their completed work; a manual Sync queues a reconciliation pass and repeated requests share the existing job. Different overlapping roots remain protected. Saving base settings also notifies the external-folder reconciler.

The durable vectorization-pending marker is not rewritten when already true. This removes a full metadata-domain write per newly indexed document during deferred vectorization. On the inspected live installation the metadata file was approximately 106 MB and DSH was writing approximately 104 MB/s before the fix. This is a metadata-write correction, not a change to model performance or OCR accuracy.

Regression tests cover pending-marker durability, saved-artifact reuse versus changed-source reparse, and concurrent sync requests with a settings change. All changes are inside the plugin and public DSH hooks. Existing embedding settings are retained.
