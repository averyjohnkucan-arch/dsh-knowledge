# dsh-knowledge v0.5.2 — Unicode safety, settings recovery, and dependency security

Version 0.5.2 fixes upstream JSON parsing errors caused by knowledge-text
truncation, restores DSH local-model settings, and updates the local text runtime
and dependency audit policy.

## Unicode text safety (#51)

- Evidence truncation, document reads, continuation, and source labels preserve
  UTF-16 surrogate pairs, including emoji, rather than creating isolated surrogates.
- Existing isolated surrogates in retrieval injection, tool output, usage hints,
  and embedding/rerank input are replaced with `U+FFFD`, preventing upstream
  providers such as DeepSeek from rejecting the request.
- Valid characters, stored source text, and UTF-16 offsets are retained. Candidate
  order is unchanged. Regression tests cover context, tools, embeddings, and reranking.

## Local-model settings and directory actions (#47)

- Resolve the optional `remote.session` namespace on demand to avoid DSH injection-gate failures.
- Resolve host directory capabilities at invocation time, supporting late registration,
  replacement services, and older interfaces without retaining stale callbacks.
- Preserve the previous path after cancellation, manual path entry, and legacy fallback actions.

## Local runtime and dependency security (#49)

- Local embedding/reranking uses Transformers.js **4.3.1** and ONNX Runtime **1.30.0**.
  OCR retains its separate runtime.
- Pin sharp **0.35.5**, fixing three high-severity advisories, and remove the old audit
  exceptions. Production audits reject high/critical findings and incomplete or failed audits.
- Invalidate readiness receipts from older embedding/rerank runtimes while keeping downloaded
  weights. Run model health validation again in Settings.

## Upgrade notes

- Upgrading from **0.5.1** requires no database migration, reindexing, or document relocation.
- Revalidate local text models; this runtime update alone does not require downloading weights again.
- Previously corrupted conversations are not repaired automatically. Start a new conversation
  or repair the affected historical messages separately if JSON errors persist.
- Existing DSH profiles may retain older dependency resolutions. The repository lockfile does
  not replace the profile lockfile. Verify all installed sharp instances are **0.35.5 or newer**.
- Managed MinerU remains experimental; this release does not expand its validation claims.

## Upstream validation record

The upstream release preparation passed `release:check`: metadata and build-policy
checks, production audit, typecheck, **579 tests across 43 files**, retrieval benchmarks,
build, package verification, and four worker-protocol smoke checks. Benchmark thresholds
passed with no budget overruns. These are historical upstream results, not a validation
claim for later fork changes.

CI covered Node.js **22.19 / 24 / 26** and native dependency/install checks on Ubuntu,
Windows, and macOS. Real desktop folder dialogs, optional real models, and MinerU
inference require separate acceptance testing.
