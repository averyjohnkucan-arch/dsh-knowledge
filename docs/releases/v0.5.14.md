# v0.5.14 — OCR first, opportunistic NVIDIA OCR

All implementation is inside the Cordis Knowledge plugin. Public `llm/stream` and the optional public model-scheduler resource guard reserve devices before foreground inference. No DSH source patches are required.

- Parsing/OCR queues across all knowledge bases take priority over bulk vectorization. Completed extracted text and regular chunks are committed first for lexical retrieval. Vectorization resumes automatically after parsing drains and yields again between batches if more documents arrive. Live search/query embeddings remain available.
- Semantic merging is deferred with a durable per-document marker, then uses saved parsed artifacts/text without repeating OCR. Existing matching vectors are preserved. New documents arriving during a vector pass cause a fresh inventory; completed work is reused after restart.
- Optional NVIDIA PP-OCRv5 execution uses isolated ONNX Runtime CUDA sessions and the same pinned local OCR weights. One or two workers are selectable in Local Models (two recommended where VRAM permits). Setup installs private dependencies; no system Python/driver changes. Missing CUDA and failed workers fall back to CPU.
- CPU, NPU and available Intel/NVIDIA lanes share measured queues. Owned GPU PIDs are shared inside the plugin so OCR and embedding workers do not mistake one another for foreground inference. Foreign GPU workloads still reserve their devices.
- Foreground inference stops scheduling GPU OCR immediately, waits for its current call for at most ten seconds, terminates the worker and observes exit before handing off. Surplus CPU OCR sessions release; one four-thread CPU OCR session and NPU work remain available. Device monitoring also withdraws GPUs when other applications become active.
- CUDA is admitted only after its provider is verified and its first page's normalized text matches CPU output. A disagreement disables that CUDA lane and retries on CPU. This favors conservative fallback over silently changing recognized evidence.

## Validation on the development machine

RTX PRO 5000 Blackwell laptop, Intel Core Ultra 9 285HX. Warm repeated scanned-page fixture, OCR only (excludes PDF rendering, initial model load and storage):

| Execution | Pages/s |
| --- | ---: |
| One four-thread CPU worker | 2.57 |
| One NVIDIA CUDA worker | 6.05 |
| Two NVIDIA CUDA workers | 12.79 |

These are synthetic fixture rates, not a promise for arbitrary documents or the full pipeline. CUDA cold startup ranged from about 2 to 10 seconds. Four rendered page checks covered scanned text, a skewed scan, a table and a chart; three normalized texts matched exactly, while a low-resolution table differed in several letters/spacing (its numeric values matched). That table is rejected by strict first-page CUDA admission and falls back to CPU.

A real CUDA worker passed text qualification and was confirmed exited 318 ms after the foreground reservation; exactly one CPU lane remained enabled and the NPU stayed enabled. Automated regressions cover ten-second forced yield, accelerator failure fallback, cross-base OCR priority, semantic deferral and vector reuse.

Reload the plugin to activate backend changes. Existing index data and the v0.5.13 saved-Markdown/folder-sync behavior are preserved.
