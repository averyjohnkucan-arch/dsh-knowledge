# v0.5.18 — Remove cross-base structure stalls and OCR reload churn

The shared parser queue now covers parsing only. Optional structure enrichment keeps its own serialized, persistent worker; waiting for that worker no longer occupies every parser slot. The existing per-source file window continues to bound outstanding documents.

For chart/table enrichment, PP-DocLayout_plus-L first examines every page using the same Paddle PDF renderer. Full PP-Structure OCR runs only on detected table/chart pages, using their original page pixels. Ordinary text stays with the regular parser and accelerated OCR. Original page numbers and empty enrichment results are retained. The full extraction mode remains available for callers that need it.

OCR device admission retains workers across gaps of up to five minutes and while OCR requests remain queued. Foreground inference still overrides that warm period and releases GPUs at the existing checkpoint/ten-second bound. No harness source or embedding settings are changed.

Validation: 709 tests passed, one skipped before the additive stage-label update; targeted checks and typecheck/build also cover that update. A three-page text-only PDF took 31.74 seconds in the old structure pass versus 4.99 seconds with layout-first enrichment, with both models initialized before measurement. A separate text/table/chart PDF preserved identical extracted table cells, chart values and page numbers. Its first full pass took 83.27 seconds including model startup and the following selective pass took 47.53 seconds; those startup conditions differ, so that mixed comparison is a correctness check rather than a controlled speedup claim. These samples do not establish a whole-corpus throughput figure.
