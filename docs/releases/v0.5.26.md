# v0.5.26 — Embedding controls and explanatory settings help

Open Knowledge, select a base, and open its settings. Vector dimensions, embedding batch size and Top K now have sliders paired with editable number boxes. Retrieval controls also expose search mode, fusion weight, context stitching and MMR relevance balance. CPU embedding performance controls use the same paired inputs. Existing settings retain their values until saved.

Hover, focus or click the circular information buttons for one or two paragraphs explaining what each setting changes and its effects on quality, latency, memory, storage and existing documents. Popovers stay above scrolling panels, support keyboard dismissal and remain readable on narrow screens.

## Vector dimensions

Qwen3 Embedding 0.6B supports 32–1024 dimensions, with 1024 as its native default. Reduced vectors use the model's Matryoshka prefix followed by L2 normalization, identically for document and query embeddings. The supported range is documented in the [official model card](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B). Other models keep native output unless supported reduction is explicitly implemented; arbitrary model vectors are never silently truncated.

Saving a different width starts background re-vectorization from saved chunks and retains their boundaries and source text. It does not request OCR or folder re-import. Incompatible vectors are excluded until replaced, while keyword retrieval remains available. Queries spanning bases with different widths use each base's configuration before merging results. Choosing the native width and choosing model default have the same vector identity.

Batch size is an upper limit; device and token limits may split it further. Top K controls returned search hits, while automatic injection also respects its own passage budget. These tuning controls do not require re-embedding. MMR is labeled as a relevance balance: zero disables it; larger enabled values favor relevance over diversity.

## Validation and scope

Targeted tests cover vector projection, validation, query/index compatibility, dimension migration with stable chunks, cross-base retrieval, numeric editing, settings persistence and help interaction. Type checking, production build and packed-artifact checks are part of the release checks. An isolated browser preview verifies paired controls, save behavior and rendered explanations without changing live knowledge bases.

The broader regression run exposed an existing lightweight read-ahead concurrency assertion that also fails on the unchanged source revision on this host. It is unrelated to these settings changes. Three storage tests that exceeded the default timeout passed when rerun with a longer limit. This release does not change OCR scheduling, inference engines or DSH core.
