# 0.5.3 — local embedding performance

Install this plugin through its GitHub link in a fresh DSH web profile. Settings → Local Models contains embedding performance controls and the optional OpenVINO CPU/NPU model installer. All installer scripts, pinned model metadata, private runtime setup, device validation and fallback code are included in this plugin. Model weights are downloaded separately; another plugin or the old Local AI application is not required.

The original ONNX Qwen3 model remains the default. Automatic CPU tuning uses two independent eight-thread processes on sufficiently large machines, with micro-batches of one. CPU count and available RAM bound the configuration. Retrieval keeps its own embedding process.

The OpenVINO model is separately selectable because its vectors are incompatible with the ONNX export. Use it for a new base or rebuild an existing base; never reuse ONNX vectors with it. CPU and NPU were tested on an Intel Core Ultra 9 285HX and Intel AI Boost. The optional GPU paths remain gated by a device self-test and verified idle state; they were not benchmarked while the desktop was active.

GPU background work stops accepting jobs on desktop activity or foreground LLM streaming. Its current job may complete for up to ten seconds, after which the owned process is terminated and the batch falls back to CPU. Unknown idle state denies GPU use. Windows uses installed device drivers; Windows hardware testing remains outstanding.

See `docs/embedding-performance.md` for measurements and limitations.

Qwen3 ONNX uses a versioned single-text vector format to avoid padding-sensitive batch vectors. Existing vectors migrate without re-chunking; incompatible formats are excluded from vector search while lexical retrieval remains available.
