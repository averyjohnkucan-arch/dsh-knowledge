# 0.5.8 — compact live progress updates

External-folder polling now fetches compact totals and connection state rather than repeatedly transferring every document header. Indexing updates request only the status of finished documents; the full document list refreshes when a pass finishes or the source revision changes. Saved processing rows are reconciled even when a job finishes before the first poll.

Document totals are aggregated by the readonly SQLite worker. Per-document embedding coverage uses the document index without loading chunk bodies or vectors. This keeps large-library progress reporting from blocking chat streaming.

All changes are contained in the plugin and its public HTTP/client integration. The external-folder reopen integration test allows 30 seconds for its two complete plugin mounts and imports; the previous five-second limit was insufficient on the loaded host.

Live tracing also found that active-ID changes repeatedly fetched approximately
47 MB of document headers. The panel now polls a compact live summary, refreshes
the full listing after source revisions or pass completion, and keeps progress
counts/ETA updating separately. Metadata aggregation runs in the same read-only
worker. Opening or explicitly refreshing a large document listing can still be
more expensive than normal progress polling.
