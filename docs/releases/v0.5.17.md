# v0.5.17 — Faster mixed PDF/OCR imports

- Encode full-resolution OCR rasters with a low-latency lossless PNG path. Six real archival-page rasters decoded to exactly identical RGB pixels; encoding fell from 251–510 ms to 49–95 ms.
- Reduce character scores to indices/confidences on CUDA before transferring them to the host. The same model weights and FP32 precision are retained. CUDA tracing verifies both reductions execute on CUDA; six real page comparisons produced exactly matching text on the same backend.
- Use a bounded persistent PDF text-parser pool. A native crash/timeout affects its own lane, buffers are transferred without detaching the caller's input, and plugin teardown terminates parser heaps.
- Use one rolling bounded file window across sibling folders. Slow files no longer hold the next batch or subfolder behind an artificial barrier.
- Schedule against measured completion time, allowing fast CUDA lanes to absorb backlog. Coordinate CPU OCR capacity with a large CUDA pool so CPU cores can feed parsing, rendering and accelerator preprocessing. CPU capacity returns when CUDA is unavailable.
- Share one successful CUDA/CPU backend comparison only across workers with matching source weight/dictionary identities and verified CUDA providers. Ambiguous pages keep CPU fallback; short/blank comparisons do not establish shared admission.
- Allow one to eight idle NVIDIA OCR workers, subject to VRAM headroom. Display ready/working/paused state and completed request counts instead of presenting calibration as proof of current activity.
- Preserve checkpoint-based GPU handoff, the ten-second maximum grace, one foreground CPU OCR session capped at eight threads, and NPU work. All integration stays inside the Cordis plugin and existing public DSH hooks. Embedding settings are unchanged.

## Corpus replay

Tested on 250 fixed PDFs containing 30,571 pages, including 756 pages requiring OCR, on an Intel Core Ultra 9 285HX, Intel NPU/iGPU, NVIDIA RTX PRO 5000 Blackwell laptop GPU (24 GB), and 128 GB RAM in performance mode. Parsing/OCR replay includes text extraction, raster encoding/transport, worker startup, recognition, and ordered result assembly; it excludes database indexing and embeddings. Identical corpus hashes were checked across runs; all 250 documents completed without failures.

The initial replay took 246.5 seconds. Lossless encoding and compact CUDA output with four simultaneous documents took 149.9 seconds with two CUDA workers, 132.2 with four, and 120.7 with eight. Parser pooling and scheduling reduced the eight-worker replay to 84.1 seconds; twelve workers took 88.1. Eight simultaneous documents took 78.2 seconds. Further CPU/startup coordination reached approximately 70 seconds. A larger recognition batch was slower (80.8 seconds); twelve CUDA workers with the final scheduler were also slower (74.4 seconds). FP16 recognition and CPU batching were evaluated and rejected because they did not improve the best measured full-precision path.

A confirmation replay finished in 71.0 seconds. Doubling Intel workers while increasing the document window to sixteen took 73.0 seconds, without improving the selected configuration.

The native handoff test unloaded eight CUDA processes and one Intel GPU process in 1.66 seconds, with 24,061 MiB NVIDIA VRAM free afterward. All sixteen queued pages completed through the retained CPU/NPU path. Automated validation: 706 passed, one skipped; type checking, build, package, workspace and release-metadata gates pass.

A separate fresh import through the live DSH plugin processed all 253 source files (250 PDFs plus three metadata files), produced 41,814 chunks, and finished in 93.7 seconds with zero failures, including chunking and database storage. Embedding remained disabled. The temporary validation KB was removed afterward; all original PDFs retained the initial corpus hash.

These are measured results on this corpus, not a universal speed or OCR-accuracy guarantee. OCR text may differ slightly across the qualified CPU, NPU and GPU backends. The public [benchmark command](../../benchmarks/ocr/README.md) is included for reproducing a full corpus replay without modifying a KB.
