# v0.5.16 — Recover NVIDIA OCR and bound foreground CPU work

- Replace exact CPU/CUDA transcription matching with normalized character-trigram agreement (95% threshold plus length coverage). Ignore punctuation, whitespace and case. Short identifiers still require an exact normalized match. This is a backend sanity check, not a claim of ground-truth OCR accuracy.
- A low-agreement qualification page uses its CPU result and retries GPU qualification on a later page after ten seconds. It no longer permanently bans a working GPU. CUDA runtime failures also retry after cooldown; provider identity remains mandatory.
- Busy healthy lanes apply backpressure instead of launching more CPU fallback sessions. Serialized lane retries release their original queue before choosing another device. Prefetch up to sixteen PDF rasters so newly admitted GPU workers can receive work even when they were absent at document start.
- While foreground inference reserves devices, stop both GPU types at checkpoints (ten-second maximum grace), retain one CPU OCR session of eight threads, one CPU embedding session of at most eight threads, and NPU lanes. Resume additional CPU workers after the last foreground reservation exits. Apply the same CPU tuning to standard local embedding requests at batch boundaries.
- All behavior remains inside the existing standalone Cordis plugin and its public `llm/stream` / optional scheduler guard integrations. No DSH source changes.

## Real archival-page checks

Four first pages from the user's archival legal scan corpus were compared using identical 1536-pixel rasters. Three were not exactly identical. Character-sequence agreement was 98.64–100%; normalized trigram agreement was 98.84–100%. All pass the new 95% sanity threshold. Warm CUDA OCR measured 294–424 ms/page versus CPU 2,758–3,708 ms/page on three of these pages (about 7–10x); the first CUDA page included 2.14 seconds of cold initialization. These measurements do not cover the entire PDF pipeline or every document.

A native CUDA worker successfully qualified on an actual archival page with differing CPU/GPU text. Foreground handoff confirmed its process exited in 182 ms, leaving one CPU OCR lane and NPU enabled. Full automated suite: 696 passed, one skipped; targeted qualification, queue backpressure and foreground handoff regressions also pass.
