# v0.5.25 — Import backpressure and lower write amplification

The old parser gate accepted eight active jobs and only sixteen waiting jobs on this host, while each folder could submit thirty-two. Concurrent knowledge bases could therefore fail valid files with “document processor queue is full.” Internal parsing now waits; global admission limits source loading before bytes are read. Large hosts admit up to 128 lightweight files and four heavy documents across knowledge bases. Nested operations share a live admission; cancellation and shutdown remove waiting work.

Concurrent document metadata writes share transactions and preserve invocation ordering relative to deletes and publications. Completed generations collect for up to 50 ms, targeting 128 documents or 16 MiB. Pending publications are bounded at 256 documents or 128 MiB, and callers wait for durable commit. SQLite's writer cache is capped at 2 GiB, reserving memory for workers and parsed data toward an 8 GiB working target. This is not an OS-enforced memory ceiling: native model footprints, individual oversized files and the rest of DSH remain variable.

Folder reconciliation retains document headers, not all source bodies. Sibling identities use indexed lookups. ETA history uses at most 120 one-second buckets. Live progress remains immediate, with diagnostic checkpoints coalesced to once per second; new remote job IDs and terminal states still persist. Startup orphan cleanup removes groups of documents rather than committing each document separately.

## Measurements and limits

An isolated, SSD-backed test of the same 256 Markdown files (6,847,378 source bytes, 4,219 chunks), including placeholders, metadata updates, publication and source signatures, measured 134,377,472 process-accounted write bytes for v0.5.24 with 32 producers versus 96,636,928 bytes with the new 128-producer configuration: 28.1% fewer writes. Two runs reproduced the same write-byte totals; elapsed times varied from 1.04–1.22 s for the baseline and 0.93–1.03 s for 128 producers. Increasing to 256 producers produced no material further reduction. Full-text index integrity and chunk counts passed. This storage benchmark simulates a 5-ms parse delay; it is not an OCR/embedding throughput claim or an SSD-controller write measurement. Raw results are in `benchmarks/import-writes-0.5.25.json`.

Full-text index construction still requires durable writes. The changes preserve retrieval semantics, evidence and crash-recovery checkpoints; no RAM disk or harness modification is required. Hardware-specific OCR/model performance is not proven by the offline test suite.

## Validation

The final suite passed 736 tests with one skipped across 68 files. Type checking, release metadata checks, packed-artifact validation and smoke tests for all four bundled workers passed. Regression tests exercise concurrent queue backpressure, cancellation, rollback, mutation ordering, close/reopen durability, orphan cleanup and immediate UI progress with bounded checkpoint writes.
