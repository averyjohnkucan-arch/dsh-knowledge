# 0.5.5 — streaming responsiveness during knowledge indexing

A 50,255-document / 5.15-million-chunk library reproduced synchronous UI status
scans blocking the host event loop for approximately 575 ms. The same exact
coverage result in a read-only worker took 620 ms overall while the largest
host heartbeat gap fell to 24 ms. The worker does not make the SQL scan disappear;
it keeps that work off the thread delivering streamed replies.

Vector-only generation updates now preserve the existing text/FTS rows after
checking every canonical text/evidence field. IDs, order, text or evidence changes
still use atomic full publication. Existing staging, metadata publication and
crash recovery remain in place.

This release changes only the knowledge plugin. It does not change sampling,
engine tuning, GPU power settings or DSH's session-stat formula. Direct tests
observed normal engine streaming: NInfer median event gap 53 ms, maximum 90 ms;
Atomic Strata 50.4–62.7 generated tokens/sec, median event gaps 19–22 ms. These are
small tests, not a guarantee for every prompt. The UI's session-wide decode rate
includes time from first token until assistant-message completion, including
stream finalization; it is not the same measurement as engine-only decode.
