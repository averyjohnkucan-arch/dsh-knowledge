# v0.5.15 — Stream PDF rasters without blocking DSH

- Move MuPDF rendering and PNG encoding from the DSH event loop into plugin-owned isolated processes. Start OCR as soon as the first raster is ready; acknowledgements bound in-flight page buffers and allow rendering to overlap recognition.
- Preserve page/raster limits, dimension checks, allocation retries, page ordering and strict failure for incomplete documents. Renderer crashes/timeouts cannot take down the host. Plugin unload stops owned render processes and prevents an interrupted OCR request from reopening a disposed CPU pool.
- Stop asking pdf.js 1.10 to decode image operator lists merely to identify textless pages. This removes a redundant image decode and its `Image is not defined` browser-global failure. Textless pages become OCR candidates, including blank pages. Verified textless PDFs use installed OCR before trying a second generic Markdown conversion.
- Retain all 0.5.14 OCR-first scheduling and optional NVIDIA workers. No DSH source changes; renderer ships in the plugin's compiled release.

Validation: 688 automated tests passed, one intentionally skipped, including new IPC tests for bounded streaming, late-page failure, OCR failure, renderer crash and deadline. A real two-page mixed PDF rendered with recognition overlapped in 370 ms while the host serviced 36 ten-millisecond heartbeat ticks. This measures rendering/dispatch with a small simulated OCR delay, not full document OCR throughput.
