# v0.5.11 — Recall feedback and accelerator recovery

Recall uses an independent request state and shows request failures in its own panel. It also reports when vector retrieval falls back to keyword search; a fallback is not presented as a successful vector lookup.

NPU query work has priority after the active request. If it has not started after five seconds, only the queued query expires and CPU handles the fallback. The active background request is preserved. Runtime failures retain bounded driver diagnostics. A failed NPU lane is requalified against CPU vectors after cooldown before it is readmitted, with longer backoff when revalidation fails. GPU lanes must pass availability and vector checks before readmission. Intel iGPU inputs above 512 tokens fall back without truncation rather than triggering arbitrary new static-shape compilations.

Failed document processing counts can be expanded to see names, codes and messages. Details are bounded to 1,000 items per run and remain in memory; failures from an older running version that retained only counters cannot be reconstructed. This is not a durable historical error log.

Deletion dialogs distinguish indexed documents and internal copies from original source files. Automatic folder sync can reimport files that remain in the selected folder.

The optional `scripts/benchmark-chunking-articles.mjs` compares plain, Smart and Semantic chunking on the same 50 hash-pinned articles using the actual plugin and native FP16 embeddings. Each trial has a fresh MemoryStore. Its metrics exclude model startup and production SQLite publication; they must not be presented as whole-library ingestion speed or retrieval-quality certification.

The update requires a plugin reload to activate host changes. Do not interrupt an in-flight large indexing or deletion operation just to activate it. No re-download of existing weights is required.
